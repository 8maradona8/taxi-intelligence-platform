# TIP Domain Blueprint v1

## Purpose

This document defines the core domain language of Taxi Intelligence Platform.

TIP is a decision intelligence system. It does not only collect data. It transforms urban activity into signals, groups them by zone, evaluates demand, and produces driver-oriented decisions.

## Core Flow

Collector
→ Service
→ SignalEvent
→ SignalEngine
→ SignalPipeline
→ Zone
→ DemandScore
→ DecisionEngine
→ Decision
→ Recommendation

## Core Domain Objects

### SignalEvent

A unified domain event generated by any intelligence module.

Examples:
- airport activity
- weather condition
- traffic condition
- event activity
- transport activity

A SignalEvent contains:
- source
- signal type
- zone name
- impact score
- confidence
- priority
- observed time
- TTL
- payload

### Zone

The primary decision entity.

A Zone represents a real-world area where a driver may operate.

A Zone owns active signals and can calculate:
- total impact score
- average confidence
- demand score

### DemandScore

A domain object representing the current demand state of a zone.

A DemandScore contains:
- score
- confidence
- level
- reasons

### Decision

A domain object produced by the DecisionEngine.

A Decision contains:
- zone
- demand score
- action
- reasons
- confidence

### Recommendation

Future domain object that transforms a Decision into driver-facing guidance.

## Architecture Rules

### Rule 1 — Domain must not depend on infrastructure

Domain objects must not import:
- SQLAlchemy
- FastAPI
- Redis
- external API clients
- repositories

### Rule 2 — Infrastructure may depend on Domain

Services, collectors, repositories, and API layers may consume domain objects.

### Rule 3 — Collectors do not make decisions

Collectors collect external data and produce or trigger SignalEvents.

### Rule 4 — DecisionEngine consumes Zones, not raw external data

DecisionEngine must not know about:
- airport APIs
- weather APIs
- traffic APIs
- event APIs

It only evaluates Zone state.

### Rule 5 — Every recommendation must be explainable

Every Decision and future Recommendation must include reasons.
